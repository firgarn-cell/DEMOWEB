1. Суть экзамена одной фразой

Нужно сделать полноценную веб-ИС (фронтенд + бекенд + БД + ООП) для записи пользователей на курсы ДПО: регистрация, вход, заявки, отзывы и админ-панель со сменой статусов. Результаты — в личный Git-репозиторий (коммиты минимум в начале и в конце каждого модуля). Интернет на экзамене недоступен.

Важно. Базу данных в день экзамена проектируете сами. Связь с СУБД проверяют в подготовительный день. Библиотеки/фреймворки берут из публичной папки сервера (офлайн).

3. Предметная область «Корочки.есть»

Портал для записи на онлайн-курсы дополнительного профессионального образования.

Пользователь

Регистрируется → входит → создаёт заявку (курс, дата, оплата) → смотрит свои заявки → оставляет отзыв (после завершения обучения).

Администратор

Логин Admin, пароль KorokNET. Видит все заявки, меняет статус: «Новая» → «Идет обучение» → «Обучение завершено».

4. Рекомендуемый стек и сдача работы

Что обычно берут на площадке

  • БД: MySQL / PostgreSQL / SQLite (что выдадут)
  • Бекенд: PHP / Python (Flask/Django) / Node.js — из офлайн-папки
  • Фронт: HTML + CSS + JS; Bootstrap / Tailwind офлайн
  • Графика: GIMP / Photoshop / Inkscape / Figma (локально)
  • Git: индивидуальный репозиторий на общем сервере
В КОД прямо сказано: полный стек — фронтенд, бекенд, БД, ООП, библиотеки/фреймворки. «Голый» HTML без сервера и БД почти наверняка снимет баллы за безопасность и модули ИС.

5. Модуль 1 — как решать (ядро экзамена)

Порядок, который реально укладывается в 90 минут:

  1. Сразу первый коммит. Пустой каркас проекта + README («старт модуля 1»). Без этого можно потерять баллы за работу с Git.
  2. Спроектировать БД и ER-диаграмму средствами СУБД (Workbench / pgAdmin / DBeaver — что есть). Экспорт ER-картинки в репозиторий.
  3. Сделать бекенд + модели (пользователь, заявка, отзыв). Хеширование паролей, сессии/токены, проверка ролей.
  4. Собрать 5 экранов с рабочей логикой (см. ниже). Красота вторична — сначала функции и валидация.
  5. Прогнать сценарии вручную: рег → вход → заявка → админ меняет статус → отзыв. Финальный коммит модуля 1.

6. База данных: минимальная рабочая схема

Сущности «на весь мир» не нужны — только то, что обслуживает функционал.

Пример SQL (ориентир)

CREATE TABLE users (
  id            INT PRIMARY KEY AUTO_INCREMENT,
  login         VARCHAR(50)  NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  full_name     VARCHAR(150) NOT NULL,
  phone         VARCHAR(20)  NOT NULL,
  email         VARCHAR(120) NOT NULL,
  role          ENUM('user','admin') NOT NULL DEFAULT 'user'
);

CREATE TABLE applications (
  id             INT PRIMARY KEY AUTO_INCREMENT,
  user_id        INT NOT NULL,
  course_name    VARCHAR(200) NOT NULL,
  start_date     DATE NOT NULL,
  payment_method ENUM('cash','phone_transfer') NOT NULL,
  status         ENUM('Новая','Идет обучение','Обучение завершено')
                 NOT NULL DEFAULT 'Новая',
  review_text    TEXT NULL,
  created_at     DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id)
);

8. Модуль 2 — дизайн и усиление UX

  1. Оптимизировать медиа из zip. Сжать JPG/WebP, выровнять размеры для слайдера (одинаковые width/height), вырезать лишнее. Исходники — в Прил_ОЗ_КОД …-М2.zip.
  2. Единый визуальный стиль. Выберите 1–2 логотипа из набора, палитру (например синий + бирюза), шрифты, кнопки, отступы. Не смешивайте все 18 картинок хаотично.
  3. Слайдер: ровно 4 кадра одинакового размера, автосмена каждые 3 секунды, кнопки «вперёд/назад», вписать в layout.
  4. Мобильные макеты 390×844. Отдельный .html на каждую страницу (регистрация, вход, заявки, новая заявка, админ) — можно статикой с CSS.
  5. Доп. функционал: ошибки валидации на форме; кнопка «Зарегистрироваться»; курс из выпадающего списка из трёх названий; дата в формате ДД.ММ.ГГГГ; отзыв только после «Обучение завершено»; в админке — фильтр / пагинация / всплывающие сообщения.

10. Модуль 3 — оптимизация и «полировка»

  1. Доведите схему БД до всех задач М1+М2 (справочник курсов, отзыв, индексы, ограничения статусов).
  2. Склейте дизайн и логику: мобильные стили через media queries (не только отдельные html-макеты), единый UI-kit.
  3. Анимации / микроанимации: появление форм, hover кнопок, плавная смена слайдов, toast при смене статуса, skeleton/loader при запросах.
  4. Качество кода: разделение на слои (model/controller/view или MVC), без дублирования валидации, понятные имена, комментарии только где нужно.
  5. Финальный коммит с тегом/сообщением «module 3 done».

12. Чек-лист перед сдачей

Частые потери баллов: plaintext-пароли; нет ER из СУБД; админ «захардкожен» только на фронте без роли в БД; слайдер без автосмены или с разными размерами кадров; мобильная вёрстка «на глаз» без 390×844; нет коммитов; интернет-CDN (на экзамене не откроется).
